# M14-T03 人工盲玩检查清单

## 目标
在不看代码、不看设计文档的前提下，模拟新玩家体验 M14 救助放归核心循环。

## 环境准备
- [ ] 启动游戏（Godot 编辑器运行或导出构建）
- [ ] 确认从新游戏或已有存档开始（至少有 3 只常驻生物以解锁码头入口）
- [ ] 计时器归零

## 第一阶段：发现（0–1 分钟）

- [ ] 是否在 1 分钟内发现底部导航栏的码头/救助入口？
- [ ] 入口按钮的视觉提示是否足够明显（颜色、文字、动画）？
- [ ] 入口按钮的文字是否传达了"这里有事情可以做"？

发现入口耗时：___ 秒

## 第二阶段：理解（1–3 分钟）

- [ ] 打开码头面板后，是否能在 3 分钟内理解"这里有受伤生物需要帮助"？
- [ ] 待救助生物的信息呈现是否清晰（物种名、状态描述、恢复预估时长）？
- [ ] "带回照料"按钮的含义是否明确？
- [ ] 带回成本（RP）是否在可接受范围内？

理解"带回救助"耗时：___ 秒

## 第三阶段：救助位理解（3–5 分钟）

- [ ] 带回生物后，是否能在 5 分钟内理解救助位的作用？
- [ ] 恢复进度条是否清晰易读？
- [ ] 恢复速度与水质/舒适度的关系是否有提示？
- [ ] 救助位与其他生物位是否有明显区分？

理解救助位耗时：___ 秒

## 第四阶段：放归（10–15 分钟）

- [ ] 是否能在 10–15 分钟内看到恢复完成（进度 100%）？
- [ ] "可放归"状态是否足够明显？
- [ ] 点击"放归大海"按钮是否顺利？
- [ ] 首次放归闭环是否在 15 分钟内完成？

首次闭环耗时：___ 秒 / ___ 分钟

## 第五阶段：结算理解

- [ ] 放归结算面板是否清楚展示了奖励内容？
- [ ] 生态声望的增加是否有意义感？
- [ ] 图鉴标记"已救助"是否清楚？
- [ ] 玩家是否理解"放归是完成救助，不是损失生物"？

## 第六阶段：后续引导

- [ ] 放归后是否清楚下一步可以做什么？
- [ ] 下一只生物的到达提示是否清楚？
- [ ] 救助位空闲后，是否知道可以再次救助？
